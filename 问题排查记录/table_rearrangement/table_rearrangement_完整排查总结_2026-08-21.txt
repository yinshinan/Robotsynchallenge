一、任务目标与最初故障现象
======================================================================

任务：排查 table_rearrangement 的失败原因。

最初从失败视频观察到两个主要现象：
1. 左右手靠近物品后，夹爪似乎都没有张开。
2. 夹爪接近物体的位置没有准确对准物体，存在横向偏移。

最初计划的最小对照实验顺序：
1. 取消夹爪二次缩放，直接把模型输出的 0～0.05 m 发给环境。
2. 同一 seed 比较 n_action_steps=50 和 1/5，观察横向偏差是否下降。
3. 把抓取 z=-0.008 暂时改成 0，或先升高 5～10 mm，排除桌面碰撞。
4. 核对并修正随机环境左右臂 joint IDs。
5. 同时记录模型原始动作、发送给环境的动作、实际夹爪物理 qpos。
6. 收紧成功判定后再统计成功率。

用户要求：不要直接修改原有代码，所有诊断逻辑都放到新文件中。

执行情况：整个排查过程中没有修改官方/原始任务和配置文件。新增内容都位于诊断脚本、诊断配置、日志和评估结果目录中。

二、当前可以确认的核心结论
======================================================================

1. 原始的“两只夹爪都没有张开”主要由夹爪动作的二次缩放导致。

诊断版 deploy_policy.py 已将 ACT 动作向量中左右夹爪的有效索引 6 和 13 作为物理米制命令直接发送，并裁剪到 [0, 0.05]，不再经过旧的二次归一化/缩放。

物理夹爪 qpos 通过运行时接口动态读取：
- left_eef 的非 mimic 主关节
- right_eef 的非 mimic 主关节

在 joint IDs 修正后的随机 20-seed 测试中：
- gripper_not_opened = 0
- ineffective_grasp = 0
- 不再出现“两边夹爪都不张开”的失败类型

因此，直接发送物理夹爪动作已经解决最初最明确的夹爪不开问题。

当前建议：继续保留物理夹爪直发方案，不要恢复旧的二次缩放。

======================================================================
三、为什么普通 fixed seed 之前不能真正复现，以及如何修复
======================================================================

最初尝试单独用同一个 seed 录制视频时，发现 fork/spoon 的初始位置与连续 20-episode 运行中的同 seed 相差 8～18 cm；原来失败的三个 seed 单独运行后变成 2 个成功、1 个失败。

根因位于原始文件：
/home/user/Robotsynchallenge/RoboSynChallenge/robosynchallenge/managers/events.py

关键机制：
1. replace_distractor_slots_from_library 使用 Python random.sample。
2. BaseEnv.reset(seed) 只调用 torch.manual_seed(seed)，没有同步 seed Python random 和 NumPy global RNG。
3. distractor event 早于 init_fork_pose/init_spoon_pose 执行。
4. _sample_positions 会根据 avoid_uids 和前一 episode 的旧物体位置进行数量不固定的 rejection resampling。
5. rejection 次数变化会消耗数量不固定的 torch RNG，导致后续 fork/spoon 初始 pose 即使 seed 相同也依赖历史 episode。

因此，旧流程中的 seed 不是独立可复现的；单 seed 结果不能与连续 20-episode 的同名 seed 直接比较。

新增可复现诊断包装器：
/home/user/Robotsynchallenge/RoboSynChallenge/scripts/eval_table_rearrangement_reproducible_diag.py

它只在复制出的诊断配置中做以下处理，不修改原始配置：
- reset 时同步 seed Python random。
- reset 时同步 seed NumPy global RNG。
- 把 randomize_distractor_slots 移到 fork/spoon 初始化之后，避免旧 episode 物体状态改变餐具初始化前的 RNG 消耗。

重复验证 seed=209652396 两次：
- fork 初始 pose 差异：0
- spoon 初始 pose 差异：0
- plate 初始 pose 差异：0
- step0 raw action 最大差异：约 1.22e-6 m
- 公共 140 步 raw action 最大差异：约 3.29e-5 m
- 两次均成功

验证记录：
/home/user/Robotsynchallenge/RoboSynChallenge/diagnostic_logs/repro_seed209652396_repeat2.jsonl

注意：该包装器解决了场景初始化的历史依赖，但底层物理/渲染仍可能存在约 1e-5～4e-5 量级的小非确定性。靠近阈值的 episode 仍可能发生成功/失败翻转，所以应称为“场景可复现”，不要称为完全 bit-exact。

======================================================================
六、grasp_z=-0.008 为什么目前不是优先项
======================================================================

配置中的 grasp_z=-0.008 主要用于 expert/action bank 生成，不会在 ACT 推理时动态修改模型输出。

因此，直接修改该参数不会改变当前 checkpoint 在 ACT eval 中输出的动作，除非重新生成 expert 数据并重新训练。

另外，两个稳定失败中 link6 到 spoon 的 z 相对量与成功案例接近，视频也显示是从 spoon 侧面错过，不是高度撞桌。

当前不建议优先继续调整 grasp_z；应该先定位导致同 seed episode 3 横向预测错误的视觉/姿态共同因素。

======================================================================
九、下一窗口最推荐的排查顺序
======================================================================

下一步不要再重复夹爪缩放、n_action_steps 或抓取 z 实验。最有信息量的工作是围绕 seed=924231285 的“edge/interior 都失败”做成对分析。

第一步：扩展 reset 和逐步日志

在新诊断文件中记录以下信息，不修改原代码：
- 完整 raw 14D model action
- 完整发送给环境的 14D action
- 左右臂全部 qpos/qvel
- 左右夹爪物理 qpos
- fork/spoon/plate 的 position + quaternion
- spoon 与右 wrist/link6 的逐步相对 XYZ
- top camera、right wrist camera 的 intrinsics/extrinsics
- 图像 hash 或保存关键帧
- distractor 的 identity、pose 和可见性/遮挡情况
- reset 后右臂初始 qpos

重点对比：
- edge 组 episode 3 / seed=924231285
- interior 组 episode 3 / seed=924231285
- 相邻成功 episode

因为改变 spoon_x 后同一 episode 仍失败，优先寻找两组共享的因素：
- spoon_y
- spoon yaw/orientation
- camera intrinsics/extrinsics
- 右腕相机视角或遮挡
- distractor 类型/位置
- 右臂初始 qpos
- fork 先行动作对后续 spoon 阶段状态的影响


第二步：做单因素、保持 RNG 消耗一致的消融

建议依次测试：
1. camera extrinsics 随机化范围设为 0。
2. camera intrinsics 随机化范围设为 0。
3. 固定 spoon yaw，但保持 x/y 随机。
4. 固定 distractor 或使用确定 distractor 布局。
5. 固定右臂初始 qpos，保留其他随机项。

重要：为了维持可比性，不要简单删除随机事件。最好把随机范围设成零或固定值，使事件仍执行并消耗相同数量/顺序的 RNG；否则可能再次因为 RNG 序列漂移而得到不可比场景。


第三步：确定因素后再决定修复策略

如果失败来自特定相机扰动、遮挡或姿态区域，更合理的正式修复通常是：
- 对问题区域定向补充训练数据；
- 增加相应视觉/姿态增强；
- 平衡低覆盖场景的采样；
- 必要时修正 observation/camera 配置。

目前证据不支持以下做法：
- 全局增加固定 X/Y Cartesian 偏置；
- 裁掉 spoon_x<0.45 的任务分布；
- 把 n_action_steps 降到 5 或 1；
- 继续把 grasp_z 当作主因；
- 再次修改原始 arm joint IDs。


第四步：最终统计

找到并实现有根据的修复后：
- 使用可复现包装器；
- 保持 n_action_steps=50；

======================================================================
十五、另一个独立配置问题：cam_high extrinsics 随机化实际未生效
======================================================================

random/gym_config.json 中 cam_high 使用 look-at 配置：

    extrinsics = eye / target / up

但 random_camera_high_extrinsics 事件传入的是：

    pos_range / euler_range

EmbodiChain 的 randomize_camera_extrinsics 实现规定：
- attach/parent 相机才读取 pos_range/euler_range；
- look-at 相机只读取 eye_range/target_range/up_range。

因此当前 cam_high extrinsics 事件对实际相机 pose 是 no-op，也不会在该分支为 pos/euler 采样。日志中 20 个 seed 的 cam_high pose 完全一致，与代码审计相符。

这不是当前两个 spoon 失败的直接原因，因为训练/评测都处在同一个 no-op 配置下；但它意味着原先预期的顶视相机外参增强并不存在。将其修正会引入新的观测分布，必须单独建配置、重新生成/补充数据并重新训练，不能和当前因果实验混在一起。
